`_v_2.0.xlsx` y se actualizó `D.re` en `frontend/index.html` (fallback offline)

## 2. Diagnóstico del esquema actual

### Problemas identificados

| Tabla actual | Problema |
|---|---|
| `regionalizacion_resumen` | **Sin columna `vigencia`** → no puede almacenar datos multi-año |

### Lo que sí aplica del esquema actual

- La estructura conceptual (región → departamento) es correcta.
- Los campos `apropiacion`, `compromisos`, `obligaciones`, `pagos` son los correctos.
- Los porcentajes de ejecución (`pct_compromiso`, `pct_obligacion`) son útiles.

## 3. Esquema propuesto

### 3.1 Tabla catálogo de departamentos (nueva)

```sql
CREATE TABLE IF NOT EXISTS dane_departamentos (
    codigo     TEXT PRIMARY KEY,    -- '05', '11', '91', etc.
    nombre     TEXT NOT NULL,       -- nombre normalizado
    region     TEXT NOT NULL        -- región a la que pertenece
);
```

### 3.2 Tabla de regionalización unificada (reemplaza las dos actuales)

```sql
CREATE TABLE IF NOT EXISTS regionalizacion (
    id               INTEGER PRIMARY KEY AUTOINCREMENT,
    bitacora_id      INTEGER REFERENCES metadatos_bitacora(id),
    vigencia         INTEGER NOT NULL,
    tipo             TEXT    NOT NULL,  -- 'departamento' | 'por_regionalizar' | 'nacional'
    region           TEXT    NOT NULL,  -- ej. 'AMAZONIA', 'ANDINA'...
    departamento     TEXT    NOT NULL,  -- nombre del dpto o 'Por Regionalizar' / 'Nacional'
    codigo_dane      TEXT    REFERENCES dane_departamentos(codigo), -- NULL para especiales
    apropiacion_mmm  DECIMAL(14,6),    -- miles de millones pesos corrientes
    compromisos_mmm  DECIMAL(14,6),
    obligaciones_mmm DECIMAL(14,6),
    pagos_mmm        DECIMAL(14,6),
    pct_compromisos  DECIMAL(5,2),     -- % comp/aprop
    pct_obligaciones DECIMAL(5,2),
    pct_pagos        DECIMAL(5,2),
    pct_participacion DECIMAL(5,2),    -- % del total general del año
    UNIQUE(bitacora_id, vigencia, region, departamento)
);

CREATE INDEX IF NOT EXISTS idx_regionalizacion_vigencia
    ON regionalizacion(vigencia, region);
CREATE INDEX IF NOT EXISTS idx_regionalizacion_dane
    ON regionalizacion(codigo_dane);
```

> **Precisión:** `DECIMAL(14,6)` para preservar precisión en departamentos pequeños (Vaupés: ~0.09 mmm en algunos años).
>
> **Totales de región:** Se computan en la API como `SUM()` agrupado por `region`, no se almacenan.

## 4. Script ETL propuesto

Archivo: `etl/load_regionalizacion.py`

### Lógica de extracción

```
Para cada hoja del Excel:
  - Detectar años en fila 4 (columnas con valor entero)
  - Detectar offsets de columna por año (Aprop=0, Comp=1, Oblig=2, Pago=3)
  - Iterar filas 6..N:
      si nombre en MAYÚSCULAS → fila de region_total → OMITIR (se recalcula)
      si nombre == 'Total general' → OMITIR
      si nombre == 'Por Regionalizar' → tipo='por_regionalizar', region='POR_REGIONALIZAR'
      si nombre == 'Nacional' → tipo='nacional', region='NACIONAL'
      si nombre en mayúsculas parcial o con tilde → tipo='departamento'
  - Calcular pct_compromisos = comp/aprop*100
  - Calcular pct_participacion = aprop_dpto / total_general_año * 100
  - Convertir millones → miles de millones: valor / 1000
  - Insertar en tabla `regionalizacion`
```

### Mapeo de nombres a código DANE

Se mantiene un diccionario en el script con variantes de nombre (con/sin tilde, abreviaciones):
```python
DANE_MAP = {
    'Amazonas': '91',
    'Caquetá': '18',
    'Bogotá, D.C.': '11',
    'Bogotá D.C.': '11',
    'Archipiélago de San Andrés...': '88',
    # etc.
}
```

### 9.2 Scripts ETL ejecutados

**`etl/load_regionalizacion.py`**
- Fuente: hoja `Regionalizacion Mar-2022-2026`.
- Cargó datos para 5 vigencias (2022–2026), 6 regiones, 32 departamentos + filas `Por Regionalizar` y `Nacional`.
- Conversión: valores en millones de pesos → miles de millones (`valor / 1000`).
- Tipos cargados: `departamento`, `por_regionalizar`, `nacional`.
- Totales de región (filas en MAYÚSCULAS) omitidos; se calculan en la API como `SUM()`.

**`etl/load_sectores_region.py`**
- Fuente: hoja `sectores_por_region`.
- Estructura de columnas: `region | sector | apropiacion | compromisos | obligaciones | pagos | vigencia`.
- Unidad en Excel: pesos → conversión `/ 1_000_000_000` para obtener mmm.
- Normalización de nombres de región: `andina→ANDINA`, `amazonas→AMAZONIA`, `pacifico→PACÍFICO`, etc.
- Resultado: **135 registros** insertados para vigencia 2026, 0 omitidos.
- Regiones cargadas: ANDINA, CARIBE, PACÍFICO, ORINOQUÍA, AMAZONIA, INSULAR.

### 9.4 Frontend — Sección 3 (todas las funcionalidades)

**Mapa Leaflet interactivo**
- Dos capas GeoJSON: **Regiones** (predeterminada) y **Departamentos**.
- Control de capas desplegable (`L.control.layers`, checkboxes independientes).
- Coroplético dinámico: intensidad proporcional al % compromisos / apropiación.
- Normalización GeoJSON→DB: `AMAZONAS→AMAZONIA`, `Región Insular→INSULAR`.
- Tema oscuro en estilos del control de capas Leaflet.

**Tarjetas de región**
- Grid auto-fill con una tarjeta por cada región (6 regiones).
- Atributos mostrados: Apropiación, Compromisos, Obligaciones, Pagos (todos en mmm).
- Tarjeta **Por Regionalizar** (estilo naranja `var(--nr)`).
- Tarjeta **Nacional** (estilo morado `var(--mo)`).
- Tarjeta **Total Inversión** (gradiente magenta, última del grid).
- Las tres tarjetas especiales no ocupan ancho completo (sin `grid-column: 1/-1`).

**Detección dinámica de vigencia**
- Variable global `_reVigencia` = `Math.max(...reRaw.map(x => x.vigencia))`.
- Todas las consultas de la sección usan `_reVigencia` como año por defecto.

**Gráfico de barras agrupadas (`barReg`)**
- 4 series: % Vigente Regionalizado, % Comprometido Regionalizado, % Vigente Nacional, % Comprometido Nacional.
- Selector de años mediante pills (radio-button estilizados); año más reciente activo por defecto.
- Permite selección simultánea de múltiples años para comparación.
- Mínimo 1 año seleccionado (impide deseleccionar todos).

**Gráfico mixto evolución (`mixReg`)**
- 2 series de barras (apropiación regionalizada mmm, apropiación nacional mmm) + 2 líneas (% compromisos reg., % compromisos nac.).
- Eje Y izquierdo: montos en mmm; eje Y derecho: porcentajes.
- Cubre todos los años disponibles (2022–`_reVigencia`).
- Título dinámico via `document.getElementById('mixRegTitle').textContent`.

**Modal de departamentos con tabs**
- Tab **Sectores**: gráfico de torta (pie) con top-6 sectores + "Otros Sectores" (7 segmentos, paleta azul DNP).
  - Canvas 260×260 px con `responsive:true, maintainAspectRatio:false`.
  - Destruye instancia anterior al cerrar modal (`destroyChart('pieSect')`).
- Tab **Departamentos**: tabla existente ordenada alfabéticamente por nombre de departamento.
- Datos cargados en paralelo con `Promise.all` (departamentos + sectores).
